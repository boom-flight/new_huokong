# IMU 异步日志设计

## 背景

`imu_service` 当前在 IMU 工作线程中直接调用 `rt_kprintf`。RT-Thread
控制台通过 USART1 逐字节轮询发送，日志发送时间可能超过一个 BMI088
陀螺仪采样周期，导致 DRDY 序号出现 overrun，进而重置静止校准累计。

本设计将 IMU 实时数据处理与控制台输出彻底解耦。日志丢失可以接受，
但日志输出不能阻塞 IMU 工作线程。

## 目标与非目标

### 目标

- IMU 工作线程不直接调用 `rt_kprintf`。
- IMU 工作线程提交日志事件时不等待、不动态分配内存、不执行格式化。
- 保留当前状态、BMI088 ID、校准完成和周期诊断日志的可观测内容。
- UART 阻塞只影响低优先级 logger 线程。
- 队列满时丢弃日志并记录丢弃数量，不影响传感器服务启动和运行。
- 保持现有 BMI088 采样、overrun 和校准语义不变。

### 非目标

- 不修改 IMU 遥测协议 v1。
- 不在 ISR 中读取 BMI088 或执行日志格式化。
- 不把 UART1 DMA 作为唯一的实时性保证。
- 不为日志增加运行时配置、持久化或远程上传功能。

## 方案选择

### 方案 A：校准期间关闭诊断日志

改动最少，但运行态仍可能因诊断日志产生采样间隙，且所有实时线程中的
同步日志风险仍然存在。不采用为长期方案。

### 方案 B：仅启用 UART1 TX DMA

DMA 可以降低 CPU 占用，但 RT-Thread 的 DMA 发送队列可能等待可用槽位。
如果 IMU 线程直接调用日志接口，仍无法证明其有界非阻塞。不采用为唯一
方案。

### 方案 C：固定消息队列 + 低优先级 logger 线程

IMU 线程使用 `rt_mq_send` 的零等待路径提交固定长度事件；logger 线程使用
阻塞式 `rt_mq_recv` 等待事件，并在自己的上下文中调用 `rt_kprintf`。
队列满时立即丢弃。该方案复用 RT-Thread IPC，边界清晰，实时线程路径
简单且可测试，作为最终方案。

## 架构

新增 `src/kernel/logging/imu_log_service.[ch]`，职责包括：

- 定义固定长度日志事件和事件类型。
- 持有静态消息队列和消息缓冲区。
- 提供 `imu_log_service_init()` 启动 logger 线程。
- 提供非阻塞 `imu_log_submit()` 提交日志事件。
- 在 logger 线程中完成字符串格式化和 `rt_kprintf` 输出。
- 提供日志丢弃计数读取接口，便于周期诊断输出。

事件只包含枚举和数值字段，不保存字符串指针。建议事件类型为：

- `IMU_LOG_STATE`：旧状态和新状态。
- `IMU_LOG_IDS`：加速度计和陀螺仪 chip ID。
- `IMU_LOG_CALIBRATION_COMPLETE`：校准完成通知。
- `IMU_LOG_DIAGNOSTICS`：SPI、overrun、时间间隔、遥测丢帧和重初始化计数。

消息队列容量固定为 8 条，消息大小固定为事件结构大小。容量不是实时
正确性的前提，日志队列满时必须立即返回失败。

logger 线程优先级低于 telemetry 线程，建议使用优先级 20、512 字节栈。
IMU 线程优先级保持 5 不变。

## 数据流

1. `imu_service_init()` 先初始化日志服务，再创建 IMU 线程。
2. IMU 线程中的状态、ID、校准和诊断函数构造固定事件并调用
   `imu_log_submit()`。
3. `imu_log_submit()` 调用 `rt_mq_send()`，等待时间必须为 0；成功入队时
   RT-Thread 会直接唤醒正在等待消息的 logger 线程。
4. 入队失败时增加日志丢弃计数并立即返回。
5. logger 线程从消息队列取出事件，在 logger 线程中格式化并调用
   `rt_kprintf()`。
6. 诊断 deadline 无论入队成功与否都推进，不能因日志队列状态造成忙轮询。

日志服务初始化失败时不回退到 IMU 线程同步输出。日志功能被禁用，
但 IMU 服务继续启动，避免可观测性故障再次升级为传感器故障。

## 配置与资源

启用 RT-Thread message queue 支持，并在 `rtconfig.h` 与对应配置文件中
保持一致。消息队列缓冲区为静态存储，不使用堆分配。

预计新增资源：

- logger 线程栈：512 字节。
- 8 条固定长度事件消息及 RT-Thread 消息队列元数据。
- 少量 logger 状态和日志丢弃计数。

当前固件静态 SRAM 使用量为 16 KiB，目标芯片 SRAM 为 20 KiB；实现后必须
重新执行固件尺寸检查，确认仍有足够余量。

## 测试策略

### 主机单元测试

- 队列按 FIFO 顺序传递事件。
- 队列满时 `imu_log_submit()` 立即失败，不修改已有事件。
- 队列丢弃计数饱和递增。
- 每种事件格式化结果与当前日志格式一致。
- 诊断事件包含最新快照计数，不读取已失效的临时对象。

### 回归测试

- 现有 BMI088、校准、IMU policy、遥测和尺寸测试全部通过。
- 现有 overrun 会重置校准的测试保持不变，证明修复没有弱化数据完整性策略。

### 上板验收

- 控制台正常连接时，静止 BMI088 在约 2 秒内完成校准。
- 控制台断开或接收端不读取时，BMI088 仍能完成校准。
- 校准期间 `gyro_overrun` 不因诊断日志增加。
- logger 被 UART 阻塞时，IMU 遥测仍持续产生，且不出现由日志引入的长间隔。
- 队列溢出时只丢日志，不改变 IMU 状态机和校准结果。

## 实施边界

本次只修改日志服务、IMU 日志调用点、RT-Thread message queue 配置和相关
测试。不重构 BMI088 驱动、不修改遥测帧格式、不改变校准阈值或样本数。
