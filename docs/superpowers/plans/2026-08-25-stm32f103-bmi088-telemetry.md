# STM32F103 BMI088 Telemetry Firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the tracked STM32F427 firmware with a reproducible STM32F103C8T6 RT-Thread v5.2.2 firmware that calibrates and samples BMI088, estimates relative attitude with float Mahony, and transmits the fixed 32-byte USART2 telemetry frame at 200 Hz.

**Architecture:** Start from the GCC `stm32f103-blue-pill` BSP and vendor the matching kernel, common STM32 drivers, CMSIS, STM32F1 device support, and HAL at immutable commits. A highest-priority static IMU thread consumes timestamped data-ready latches, owns BMI088 state/calibration/estimation and publishes a double-buffered snapshot; a second static thread encodes snapshots and non-blockingly queues USART2 DMA. Platform-independent protocol, estimator, calibration, timestamp, driver, and IMU decision logic are built and tested natively with C11 assertions.

**Tech Stack:** C11, RT-Thread v5.2.2, STM32CubeF1 HAL/CMSIS, ARM Cortex-M3 GCC (`arm-none-eabi-gcc`), SCons, host C compiler assertions, OpenOCD/ST-Link, USART2 DMA.

**Spec:** `docs/superpowers/specs/2026-08-25-stm32f103-bmi088-telemetry-design.md`

- The MCU is exactly STM32F103C8T6, Cortex-M3 at 72 MHz from the board's 8 MHz HSE. Build with `-mcpu=cortex-m3 -mthumb`; do not use FPU or hard-float flags.
- The linker memory map is exactly Flash `ORIGIN = 0x08000000, LENGTH = 64K` and SRAM `ORIGIN = 0x20000000, LENGTH = 20K`. Do not rely on unofficial 128 KB Flash.
- Design limits are at most 52 KB Flash (`text + data <= 53248`) and 16 KB statically occupied SRAM (`data + bss <= 16384`); hard linker limits remain 64 KB and 20 KB.
- HAL directly owns SPI1, TIM2, BMI088 GPIO/EXTI, and USART2/DMA1 Channel 7. RT-Thread's device framework owns only the USART1 console. No peripheral may be initialized or serviced by both layers.
- Keep RT-Thread at 1000 ticks/s. Enable only static application threads, static event notification, GPIO pin support for PB6 state indication, and USART1 console support. Disable FinSH, filesystem, networking, USB, CAN, package features, and unrelated drivers.
- Application code performs no dynamic allocation after initialization. Both application threads, their stacks, the event object, snapshots, protocol buffers, driver state, and DMA state are statically allocated.
- RT-Thread uses smaller numeric values for higher priority. Configure main at priority 10, the static IMU thread at priority 5 with a 768-byte stack, and the static telemetry thread at priority 15 with a 512-byte stack.
- Compile RT-Thread and vendored dependencies globally as GNU C11 without global `-Wall`, `-Wextra`, or `-Werror`. Apply strict `-std=c11 -Wall -Wextra -Werror` only through first-party groups' supported `LOCAL_CCFLAGS`; host tests remain strict C11. Link the target with `libm` for `sqrtf`, `atan2f`, `asinf`, and `lroundf`.
- Telemetry acceleration is calibrated BMI088 body-frame specific force in g, including gravity. It is not gravity-compensated linear acceleration. No gravity vector is subtracted before snapshot publication or frame encoding.
- The newest accelerometer sample controls Mahony correction validity. A newly read out-of-gate sample immediately disables correction; a changed but not yet consumed accelerometer sequence also disables correction; an old valid vector is never reused. Stale means no new accelerometer sequence for 5 ms (`5000 us`) at the current gyro timestamp.
- Gyro `dt` in the inclusive `500..2000 us` interval integrates. `dt < 500 us` or `2000 < dt <= 20000 us` skips that interval while preserving estimator validity. `dt > 20000 us` skips and clears estimator validity. Every rejected interval records its timestamp as the new baseline; only the following valid interval can integrate.
- The signed sensor-to-body axis map must be a right-handed signed permutation with determinant `+1`. The initial map is identity: body X=`+sensor X`, body Y=`+sensor Y`, body Z=`+sensor Z`. Reject an invalid map in host tests and fail sensor initialization if the compiled map is invalid.
- Mahony gains are canonical/full-error `Kp=0.2` and `Ki=0.0`. Preserve the RMCS half-error equations by applying `two_kp = 2*Kp = 0.4` and `two_ki = 2*Ki = 0.0` to `halfex/halfey/halfez` exactly as `rmcs_ws/src/rmcs_core/src/hardware/device/bmi088.hpp` does.
- `mahony_invalidate()` preserves the last finite quaternion and clears only estimator validity and integral feedback. A later accepted gyro interval integrates from that quaternion and restores validity; a `mahony_update()` call with non-finite or out-of-range `dt` is a complete no-op and does not classify service timing.
- BMI088 settings are accelerometer +/-6 g at 800 Hz with active-low push-pull INT1 data-ready, and gyroscope +/-2000 deg/s at 1000 Hz with active-low push-pull INT3 data-ready. SPI1 is blocking and approximately 9 MHz; no ISR accesses SPI.
- PB12 and PB14 share `EXTI15_10_IRQn`. The ISR checks and clears each pending line independently, captures TIM2 once for each asserted source, updates that source's latest timestamp and sequence, sends the corresponding RT-Thread event bit, and does no SPI, float, logging, or encoding work.
- Calibration requires 2000 consecutive accepted gyro samples. Acceptance is accel norm in inclusive `0.9..1.1 g`, gyro norm strictly below `3 deg/s`, and valid timestamps. Movement resets count and sums. Calibration produces gyro bias and mean gravity, is rerun after every complete sensor initialization, and is never persisted.
- The 32-byte protocol, offsets, little-endian encoding, scales, saturation, CRC-16/CCITT-FALSE parameters, and status bits are exactly those in the linked spec. Reserved status bits 9-15 are always zero.
- USART2 is 115200 8-N-1 TX-only on PA2 with DMA1 Channel 7. Telemetry attempts a frame every 5 ticks; attempted-frame sequence advances even on a drop. DMA contention drops only the current frame and sets sticky status bit 8 until a later frame is successfully queued.
- USART1 logging is limited to startup, identity values, calibration completion, state transitions, and rate-limited error summaries. There is no text output in high-frequency paths.
- Hardware-only verification of BMI088 `PS` selection and physical mounting/axis orientation remains pending. The schematic shows a configurable `PS` net and does not establish body orientation; neither check may be declared complete without the board.

Use this complete encoder core; `put_u16`/`put_u32` explicitly write little-endian bytes and `encode_i16` returns 0 for non-finite input, rounds with `lroundf`, and clamps to `INT16_MIN..INT16_MAX`:

```c
uint16_t imu_telemetry_crc16_ccitt_false(const uint8_t *data, size_t length)
{
    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < length; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (unsigned bit = 0; bit < 8; ++bit)
            crc = (crc & 0x8000u) ? (uint16_t)((crc << 1) ^ 0x1021u)
                                  : (uint16_t)(crc << 1);
    }
    return crc;
}

{
```

```c
    snapshots[next] = *value;
    rt_base_t level = rt_hw_interrupt_disable();

{

    rt_base_t level = rt_hw_interrupt_disable();

    rt_hw_interrupt_enable(level);
    return true;

    rt_hw_interrupt_enable(level);
}
```

- [ ] **Step 1: Write the size gate and its executable host shell test**

`.script/check-size.sh` accepts an ELF path defaulting to `rt-thread.elf`, requires that file to exist, obtains decimal `text data bss` from `${SIZE_TOOL:-arm-none-eabi-size}`, computes `flash=text+data` and `static_ram=data+bss`, prints both, and exits nonzero for `flash>53248` or `static_ram>16384`. It invokes `${OBJDUMP_TOOL:-arm-none-eabi-objdump} -h` to validate section origins and verifies exact `ROM=64K` and `RAM=20K` declarations in `${LINKER_SCRIPT:-board/linker_scripts/link.lds}`. Tool overrides exist solely to test the real script; production builds use the defaults.

Implement the executable script as:

```sh
#!/bin/sh
set -eu

elf=${1:-rt-thread.elf}
size_tool=${SIZE_TOOL:-arm-none-eabi-size}
objdump_tool=${OBJDUMP_TOOL:-arm-none-eabi-objdump}
linker_script=${LINKER_SCRIPT:-board/linker_scripts/link.lds}

test -f "$elf"
test -f "$linker_script"
set -- $("$size_tool" "$elf" | tail -n 1)
test "$#" -ge 3
text=$1
data=$2
bss=$3
case "$text:$data:$bss" in
    *[!0-9:]*) echo "non-decimal size output" >&2; exit 1 ;;
esac

flash=$((text + data))
static_ram=$((data + bss))
printf 'Flash: %s bytes; static SRAM: %s bytes\n' "$flash" "$static_ram"

if test "$flash" -gt 53248; then
    echo "Flash design limit exceeded: $flash > 53248" >&2
    exit 1
fi
if test "$static_ram" -gt 16384; then
    echo "SRAM design limit exceeded: $static_ram > 16384" >&2
    exit 1
fi

sections=$("$objdump_tool" -h "$elf")
printf '%s\n' "$sections" | grep -Eq '[[:space:]]08000000[[:space:]]+08000000'
printf '%s\n' "$sections" | grep -Eq '[[:space:]]20000000[[:space:]]+[0-9A-Fa-f]{8}'
grep -Eq 'ROM[[:space:]]*\(rx\).*ORIGIN[[:space:]]*=[[:space:]]*0x08000000.*LENGTH[[:space:]]*=[[:space:]]*64K' "$linker_script"
grep -Eq 'RAM[[:space:]]*\(rwx\).*ORIGIN[[:space:]]*=[[:space:]]*0x20000000.*LENGTH[[:space:]]*=[[:space:]]*20K' "$linker_script"
```

```sh
#!/bin/sh

Sections:
Idx Name          Size      VMA       LMA       File off  Algn
```
